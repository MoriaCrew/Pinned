# 18 — Languages (i18n, PIN-23)

Pinneds shows in the visitor's language when we support it, and
anyone can switch language, back to English included, from the
"you" menu. Parent issue PIN-23; this page lands with PIN-190 and
grows with its siblings.

## Decisions (Oct 31)

- **Languages:** English (source and fallback), French, Spanish,
  Portuguese (Brazil), German, Italian, Indonesian
  (`src/i18n/locales.ts`, `LOCALES`).
- **Register:** informal everywhere — fr *tu*, es *tú* (Latin
  American, no *vosotros*), pt-BR *você*, de *du*, it *tu*, id
  *kamu*.
- **Which language a request gets:** the saved choice (cookie
  `pinneds_locale`, life `Policy.localeCookieDays`) if that
  language is on, else the best `Accept-Language` match (exact
  tag, then same base language: `pt-PT` → `pt-BR`, `es-419` →
  `es`), else English. `negotiateLocale` in `src/i18n/locales.ts`.
- **No language in URLs.** Friends share one board link and each
  sees it in their own language.
- **In-house `src/i18n`**, no library: `t` / `tf` / `tCount` with
  typed keys, `Intl` for plurals, money, dates and lists.
- **Latin-script languages only for now.** The self-hosted fonts
  are subset to about 220 Latin-1 glyphs: no Polish, Turkish,
  Vietnamese, Cyrillic, CJK, Arabic or Devanagari yet.
- **Stays English for now:** AI output (pin names, scene text),
  lab pages, link-preview images (crawlers send no language),
  Stripe product names. Follow-ups in PIN-200. Idea chips are the
  exception since PIN-214 (below).
  Name tags never auto-hyphenate (PIN-225): the page language
  would break an English or renamed name by the wrong rules.

## Turning languages on

`UI_LOCALES` (`src/config.ts`) is a comma list, e.g.
`UI_LOCALES=en,fr,es,pt-BR,de,it,id`. Unknown codes are dropped
and English is always on. **Default in `src/config.ts`: English
only.** PIN-199 turned all seven on for the **dev** backend through
`apphosting.dev.yaml`; PIN-209 turned them on for **prod** in
`apphosting.prod.yaml` from the first promotion (see "Turning prod
on").

With English only, `getLocale()` never reads the request, so pages
render exactly as before (static ones stay static). With more than
one language, the root layout reads cookies and headers, which
makes every page dynamic. Hosted, `UI_LOCALES` must also be
available at **build** time: a page prerendered with English only
stays English.

## Using it in code

- **Client components:** `const locale = useLocale();` from
  `src/i18n/client`, then `t(locale, "board.title")`.
- **Server components, `generateMetadata`, route handlers:**
  `const locale = await getLocale();` from `src/i18n/server`.
- **Counts:** `tCount(locale, "meta.things", n)` with `.one` and
  `.other` keys. The form follows the language's own rule (French
  says "0 création"); a language that hasn't translated the
  message uses English's rule.
- **Money, dates, lists:** `formatMoney(locale, cents, "EUR")`,
  `formatDate(locale, ms, options)`, `formatList(locale, items)`
  from `src/i18n`.
- **Never `t("en", …)` in new code.** `src/i18n/no-hardcoded-locale.test.ts`
  fails on any file not listed in `src/i18n/en-only-files.ts`.
  That list only shrinks: each PIN-23 child deletes its own block.

## Server errors (PIN-196)

- User-facing server errors (`BoardApiError`, `PhotoIntakeError`,
  `SceneJobRequestError`, `BoardPlusError`) take
  `userMessage(key, values)` from `src/i18n/user-message.ts`, not
  text. `.message` keeps the English for logs; `code` and status are
  unchanged.
- `errorResponse` / `plusErrorResponse` translate it with the
  request's language. Their signature stays sync: with more than one
  language the JSON body is a one-chunk stream that waits for
  `getLocale()`; with English only it is built at once, as before.
- 404 "not found" lines stay plain text (the uniform 404 hides them).
- Stored lines keep the key: a refused scene stores
  `refusalReason: "ai.refused"`; the view leaves a key out and the
  client shows its own line. Older docs keep their English (no
  migration).
- The tap fallback label ("My find") is a pin's name, so it stays
  English with the other pin names (PIN-200).

## Idea chips (PIN-214)

Idea chips follow the UI language since PIN-214. The Make sheet's
fixed chips are catalog keys (`make.chip.*`, `FIXED_CHIP_KEYS` in
`src/domain/chips.ts`); Policy keeps only how many show
(`sceneChipsCount`). The board page sends them in the viewer's
language, and the chips route passes `getLocale()` down to Muse
Spark, whose prompt `chips.v2` names the language
(`LOCALE_ENGLISH_NAMES` in `src/i18n/locales.ts`) and keeps pin
labels as they are. The 24 h chips cache is keyed by prompt
version, language and label set, so French and German viewers of
the same picks never share an entry, and chips.v1 (English) entries
are never served again. Until the translate run fills
`make.chip.*`, the fixed chips fall back to English like any other
key.

## Words (PIN-202)

One word per idea, in every language. The glossary
(`src/i18n/glossary.json`) holds each language's term.

- **Pin** (FR *épingle*, others *pin*): a cut-out object on a board
  or in My pins. Never "thing" (FR *chose*) in UI text. Counts read
  "6 pins". Code and key names (`meta.things`, `{thing}`) keep the
  old word; only the text changed.
- **Pin it** is also the verb: "Pick what to pin", "Pin 3".
- **Cut out** describes what we do to a photo ("we cut out what's in
  it"). For the real object in a photo, drop the noun ("tap right in
  the middle of it").
- **Sticker** is only the look (white edge, Foil stickers, sticker
  sheets), not the object's name.
- **Board**, **scene**, **creations** (makes) as before.
- Tagline: **"Your stuff, pinned together."** (FR *« Nos trucs,
  épinglés ensemble. »*).

## Adding a string

1. Add the key to `src/i18n/messages/en.json` **inside its prefix
   group**, never at the end of the file (parallel PRs touch this
   file all the time).
2. Write whole sentences with `{placeholders}`. Don't glue
   translated pieces together: word order differs by language.
3. Don't edit the other language files by hand. Missing keys fall
   back to English; the translation script (PIN-189) fills them.

## Adding a language

1. Check the fonts cover its script (see above).
2. Add the code to `LOCALES`, its own name to `LOCALE_NAMES` and
   its English name to `LOCALE_ENGLISH_NAMES` (AI prompts, PIN-214)
   in `src/i18n/locales.ts`, an empty `{}` catalog in
   `src/i18n/messages/`, and the import in `src/i18n/index.ts`.
3. Translate it with the script, then add it to `UI_LOCALES`.

## Translations

Made and maintained by a dev-time script that calls Muse Spark
Open on Baseten (PIN-189); never at app runtime and never in test
CI. It needs `BASETEN_API_KEY` in the environment or `.env.local`
(never printed, never committed).

### Workflow

```
npm run i18n:translate -- --all                 # delta, every locale
npm run i18n:translate -- --locale it           # delta, one locale
npm run i18n:translate -- --locale fr --force --keys a.b,c.d
npm run i18n:check                              # offline: parity, placeholders, glossary
```

1. Add or change English in `src/i18n/messages/en.json`.
2. Run the delta. Each `<locale>.lock.json` maps every key to a
   hash of its English text plus the prompt version, so only new or
   changed English is sent. Nothing else is touched.
3. Every batch gets a second **reviewer pass**
   (`prompts/review-ui.v1.md`) that fixes register, glossary terms
   and placeholders. The script prints calls, tokens, reviewer fixes
   and USD (stops at `--max-usd`, default 5).
4. `npm run i18n:check` must show every language complete (run it
   by hand). `ui.plusPerkSkinsBody` repeats the `skin.*` names, so
   after a run check they still match, and that "Board Plus" stays
   untranslated.

**Hand edits survive.** The lock changes only when the English text
or the prompt version changes, so fix a string in the locale file
directly and it stays. If the English changes, the delta overwrites
the hand edit, so redo it. `--force` retranslates the selected keys,
including hand-edited ones: scope it with `--keys`. Before you run
`--all` after another PR hand-edited a locale, expect that those
keys may be rewritten.

**Glossary and register.** `src/i18n/glossary.json` fixes the terms
that must not drift per language (pin, board, scene, creation,
"Board Plus", brand names) and the register rules sit in
`prompts/translate-ui.v1.md`. Change a term there, then re-run the
affected keys with `--force --keys`.

### Adding a language

1. Check the fonts cover its script (Latin-1 only for now).
2. Add the code to `LOCALES`, its name to `LOCALE_NAMES` and its
   English name to `LOCALE_ENGLISH_NAMES` in
   `src/i18n/locales.ts`, an empty `{}` catalog in
   `src/i18n/messages/<code>.json`, and the import in
   `src/i18n/index.ts`.
3. Add a register line to `prompts/translate-ui.v1.md` and its fixed
   terms to `src/i18n/glossary.json`.
4. `npm run i18n:translate -- --locale <code>`, then
   `npm run i18n:check`.
5. Screenshot it at 390px (landing, board, and for long languages
   the sheets and the Language list) and fix any clipping with CSS,
   never by changing the meaning.
6. Add it to `UI_LOCALES` on dev first.

### Turning prod on

Robin chose all seven languages for prod on Oct 31 (PIN-209) and
signed off the French on dev.pinneds.com the same day (after the
PIN-202 "pins, not things" pass), so `apphosting.prod.yaml` carries
the same line as dev (a plain `value:` is available at build and
runtime, which `UI_LOCALES` needs):

```yaml
  - variable: UI_LOCALES
    value: en,fr,es,pt-BR,de,it,id
```

So the seven languages go live with the next `dev` → `main`
promotion. Before each promotion, new English strings must not reach
prod untranslated: the pre-flight in `docs/DEPLOY.md` (§3, step
"Translations complete") runs `npm run i18n:check -- --strict`, which
fails while any language misses a string; if it does, run the
translate delta on `dev` (PIN-223, PIN-227) and Robin reads the French
for the new strings on dev.pinneds.com. The smoke (§5) checks French,
a saved English choice and an unknown language on pinneds.com.

To roll back, remove the line (or list fewer codes) in
`apphosting.prod.yaml` and promote: visitors fall back to English,
and saved language cookies for a language that is off are ignored.
