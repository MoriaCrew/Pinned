# 18 — Languages (i18n, PIN-23)

Pinneds shows in the visitor's language when we support it, and
anyone can switch language, back to English included, from the
"you" menu. Parent issue PIN-23; this page lands with PIN-190 and
grows with its siblings.

## Decisions (Oct 31)

- **Languages:** English (source and fallback), French, Spanish,
  Portuguese (Brazil), German, Italian, Indonesian
  (`src/i18n/locales.ts`, `LOCALES`).
- **Register:** informal everywhere — fr *tu*, es *tú* (Latin
  American, no *vosotros*), pt-BR *você*, de *du*, it *tu*, id
  *kamu*.
- **Which language a request gets:** the saved choice (cookie
  `pinneds_locale`, life `Policy.localeCookieDays`) if that
  language is on, else the best `Accept-Language` match (exact
  tag, then same base language: `pt-PT` → `pt-BR`, `es-419` →
  `es`), else English. `negotiateLocale` in `src/i18n/locales.ts`.
- **No language in URLs.** Friends share one board link and each
  sees it in their own language.
- **In-house `src/i18n`**, no library: `t` / `tf` / `tCount` with
  typed keys, `Intl` for plurals, money, dates and lists.
- **Latin-script languages only for now.** The self-hosted fonts
  are subset to about 220 Latin-1 glyphs: no Polish, Turkish,
  Vietnamese, Cyrillic, CJK, Arabic or Devanagari yet.
- **Stays English for now:** AI output (thing names, chips, scene
  text), lab pages, link-preview images (crawlers send no
  language), Stripe product names. Follow-ups in PIN-200.

## Turning languages on

`UI_LOCALES` (`src/config.ts`) is a comma list, e.g.
`UI_LOCALES=en,fr,es,pt-BR,de,it,id`. Unknown codes are dropped
and English is always on. **Default: English only**, so nothing
changes for users until PIN-199 turns languages on.

With English only, `getLocale()` never reads the request, so pages
render exactly as before (static ones stay static). With more than
one language, the root layout reads cookies and headers, which
makes every page dynamic. Hosted, `UI_LOCALES` must also be
available at **build** time: a page prerendered with English only
stays English.

## Using it in code

- **Client components:** `const locale = useLocale();` from
  `src/i18n/client`, then `t(locale, "board.title")`.
- **Server components, `generateMetadata`, route handlers:**
  `const locale = await getLocale();` from `src/i18n/server`.
- **Counts:** `tCount(locale, "meta.things", n)` with `.one` and
  `.other` keys. The form follows the language's own rule (French
  says "0 création"); a language that hasn't translated the
  message uses English's rule.
- **Money, dates, lists:** `formatMoney(locale, cents, "EUR")`,
  `formatDate(locale, ms, options)`, `formatList(locale, items)`
  from `src/i18n`.
- **Never `t("en", …)` in new code.** `src/i18n/no-hardcoded-locale.test.ts`
  fails on any file not listed in `src/i18n/en-only-files.ts`.
  That list only shrinks: each PIN-23 child deletes its own block.

## Adding a string

1. Add the key to `src/i18n/messages/en.json` **inside its prefix
   group**, never at the end of the file (parallel PRs touch this
   file all the time).
2. Write whole sentences with `{placeholders}`. Don't glue
   translated pieces together: word order differs by language.
3. Don't edit the other language files by hand. Missing keys fall
   back to English; the translation script (PIN-189) fills them.

## Adding a language

1. Check the fonts cover its script (see above).
2. Add the code to `LOCALES` and its own name to `LOCALE_NAMES`
   in `src/i18n/locales.ts`, an empty `{}` catalog in
   `src/i18n/messages/`, and the import in `src/i18n/index.ts`.
3. Translate it with the script, then add it to `UI_LOCALES`.

## Translations

Made and maintained by a dev-time script that calls Muse Spark
Open on Baseten (PIN-189); never at app runtime and never in test
CI. Usage, costs and the review routine are added here with
PIN-199.
